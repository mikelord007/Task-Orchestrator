# `fixtures/github_cache/`

Recorded GitHub REST responses. This directory is what makes the `github_triage`
evaluator deterministic, offline and free.

Caching happens at the **REST-call level**, one layer below what an agent
calls. The agent sees four consolidated, task-shaped tools
(`github_get_issue_context`, `github_search_similar_issues`,
`github_get_label_taxonomy`, `github_find_component_owners`, in
`backend/toolbox/github_tools/`, per PLAN_ADDENDUM.md section F); each one
composes several of the internal primitives in `backend/toolbox/github.py`
(`get_issue`, `list_issue_comments`, `search_issues`, `list_labels`,
`get_issue_timeline`, `get_commit`, `list_recent_commits`, `get_file`, ...).
Every primitive call is cached separately, so a composite tool's output is
exactly reproducible as long as its underlying REST calls are.

Every file is `<sha256>.json`, where the key is

```
sha256(json.dumps({"tool": <tool name>, "args": <args, empty values dropped>},
                  sort_keys=True, separators=(",", ":")))
```

and the contents are:

```json
{
  "request":    {"tool": "github_get_issue", "args": {"repo": "...", "number": 202}},
  "response":   { ...the trimmed response the tool returns... },
  "fetched_at": "2024-03-11T12:00:00+00:00"
}
```

## How it is populated

Reads hit this cache first, so eval runs never touch the network. To record a
response you do not have yet, run once with a token and live mode on:

```bash
GITHUB_TOKEN=ghp_... GITHUB_LIVE=1 GITHUB_REPO=Untrivial-ai/agent-orchestrator ...
```

`GITHUB_LIVE=1` bypasses the cache *read* but still writes it. Without a token,
a cache miss returns an error string naming the missing key — the tool never
raises and never invents data.

## Redaction

The stored response is always the **unredacted** one. When
`contracts.context.current_case` names an issue, that issue's
maintainer-applied fields (`labels`, `assignees`, `assignee`, `milestone`,
`state`, `closed_at`, `state_reason`) and its comments are withheld **on read**,
never on write. One cache therefore serves both the graded run and the agent's
exploration of the rest of the repo.

Environment: `GITHUB_REPO`, `GITHUB_TOKEN`, `GITHUB_CACHE_DIR` (defaults to this
directory), `GITHUB_LIVE`.

The recorded fixture the tests run against lives separately at
`backend/tests/fixtures/github_cache/` and is regenerated by
`backend/tests/fixtures/build_github_cache.py`.
